# Backup and recovery
GitHub is the canonical project store. Commit and verify every meaningful change remotely. On another computer, sign into GitHub with authorized access, open or clone the private repository, read RULES.md and docs/HANDOFF.md, and follow setup instructions. Temporary local copies are disposable. Use Git history to recover earlier versions; avoid destructive force pushes. Never commit credentials. Git history is not an independent backup against account/repository loss; document any future approved remote backup and external service recovery procedures. No independent backup has been verified yet.
