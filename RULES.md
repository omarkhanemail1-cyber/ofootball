# O-FOOTBALL — Project rules

Living document. Read before every development session. Add or revise rules when the owner requests changes; preserve unrelated rules and record changes in Git history.

## Owner rules
1. GitHub is the sole canonical project storage. Always read the latest remote files before editing and save all project changes to GitHub.
2. Never depend on the owner's laptop for persistent file storage. Temporary testing copies are disposable. The project must be portable to another computer.
3. Google Drive is not required for project development.
4. If GitHub access or uploads fail, report the blocker; do not silently store work elsewhere.
5. Keep the 30-day roadmap, current status and developer/AI handoff instructions in GitHub and update them as development progresses.

## Maintenance safeguards
- Verify remote writes before reporting success. Never commit passwords, tokens or private user data.
- Preserve existing working features; test changes and report incomplete or unverified work honestly.
- Document external hosting, dependencies and recovery steps when applicable.

## Additional owner-approved rules
6. Never remove existing features without owner permission.
7. Follow the 30-day development roadmap.
8. Record every new idea in GitHub.
9. Test every feature before marking it complete.
10. Fix existing bugs before introducing major features.
11. Never restart the entire game without owner approval.
12. Ask permission before changing major designs or game mechanics.
13. Create a GitHub commit after every meaningful update.
14. Update developer handover instructions after every milestone.
15. Never claim an unfinished feature is complete.
16. Prioritize realistic 3D football gameplay over decorative features.
17. Use original or properly licensed graphics, music and assets.
18. Never spend real money without permission.
19. Optimize for lower-end computers and mobile devices.
20. Maintain a changelog of every major update.
21. Protect personal information and account credentials.
22. Keep World Cup mode a major development priority.
23. Never change currency names, rewards or transfer prices without approval.
24. Explain major technical decisions in simple English.
25. The project owner has final creative authority.
26. End-of-day rule: When the owner says “done for the day,” stop starting new development work. Wrap up briefly, ensure meaningful completed changes are saved to GitHub, record only essential progress, blockers and the next starting point as needed, and stop. Do not create unnecessary files or save every conversational detail. Resume from GitHub when the owner returns; do not continue development in the background.

## Golden rule
Never lose, forget, overwrite or falsely report project progress. Document important decisions and milestones in GitHub.

## Tracking files
Maintain CHANGELOG.md, BUGS.md, IDEAS.md, DECISIONS.md, BACKUP.md and FEATURES.md as relevant changes occur.
